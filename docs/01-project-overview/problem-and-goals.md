# Problem Statement & Goals

## Context

Online job search is spread over many platforms, each with its own search interface, filters, application forms and login. A candidate who wants a good outcome typically has to monitor several boards daily, read dozens of descriptions to see which ones match their skills, tailor a resume and cover letter for each position, and retype the same personal data into a different form every time. Tracking where and when applications were sent usually ends up in a spreadsheet or in memory.

Existing automation tools tend to fall into two groups. Cloud "auto-apply" services require users to hand over platform credentials and personal data to a third party. Simple browser scripts break whenever a platform changes its page layout. The project operates in the HR-tech / productivity-tool domain and targets the gap between them: automation that keeps personal data on the user's device and survives layout changes.

## Problem Statement

**Who:** Active job seekers, especially in IT, who apply to many positions across several job platforms.

**What:** Finding suitable vacancies, assessing fit, tailoring application materials and submitting applications is slow, repetitive and error-prone. Tools that automate it either put personal data at risk or stop working when the target site changes.

**Why:** Time spent on mechanical work is time not spent on preparation and networking. Poorly tailored applications lower the response rate, and entrusting credentials to third-party services is a real privacy and account-security risk.

## Pain Points

| # | Pain Point | Severity | Current Workaround |
|---|---|---|---|
| 1 | Vacancies are scattered across many platforms and must be checked manually every day | High | Bookmarks, email alerts, manual daily browsing |
| 2 | Hard to tell quickly whether a vacancy matches the resume; each description must be read in full | High | Reading every description, guessing |
| 3 | Writing a tailored cover letter and adapting the resume for each vacancy is time-consuming | High | Generic template letter, or copy-paste from previous applications |
| 4 | The same personal data is retyped into a different application form on every platform | Medium | Browser autofill|
| 5 | No single place to track which applications were sent and what their status is | Medium | Spreadsheet or notes |
| 6 | Existing auto-apply services require handing over credentials and personal data | High | Avoiding automation at all |
| 7 | Scrapers and scripts break when a platform changes its layout | Medium | Waiting for the tool author to fix it, manual edits |
| 8 | Candidates do not know which skills are most in demand for their target role | Low | Reading postings by hand and noting recurring requirements |

## Before / After

| Aspect | Before | After |
|---|---|---|
| Finding vacancies | Visit each platform separately and apply filters by hand | Searches run in the background; results appear in one dashboard |
| Assessing fit | Read each description and compare with the resume mentally | Automatic match score between the resume and vacancy requirements |
| Cover letter | Written by hand or generic template | Personalized letter generated by the AI assistant, editable before sending |
| Submitting an application | Fill in a new form every time | Form fields mapped and filled automatically; manual or semi-automated mode |
| Tracking | Spreadsheet maintained manually | Statuses tracked automatically in the dashboard |
| Personal data | Spread across platforms or handed to a third-party service | Stored locally on the user's device |
| Platform layout changes | Tool breaks until fixed manually | Updated selectors delivered by the server without reinstalling the extension |
| Market insight | None | Hot-words analytics on in-demand skills |

## Business Goals

| Goal | Description | Success Indicator |
|---|---|---|
| G1. Reduce effort per application | Automate search, matching, letter writing and form filling | Median time per application decreases substantially against a manual baseline |
| G2. Protect user privacy | Keep personal data, tokens and credentials on the client | No personal data or credentials reach the server |
| G3. Resilience to platform changes | Distribute selector updates centrally without releasing a new extension | A broken selector is fixed for all users without an extension update |
| G4. Improve application quality | Tailor letters and prioritize vacancies by match score | Users can sort and filter vacancies by match score; generated letters reference vacancy-specific requirements |
| G5. Provide market insight | Aggregate skills data from collected vacancies | Hot-words analytics available for roles with enough collected vacancies |

## Objectives & Metrics

Baselines are estimates for a manual process and are to be validated during testing.

| Objective | Metric | Current Value | Target Value | Timeline |
|---|---|---|---|---|
| Faster applications | Median time to submit one application | ~10–15 min | ≤ 2 min of user attention (semi-automated) | MVP release |
| Reliable form filling | Share of known-platform forms filled correctly without edits | n/a (manual) | ≥ 80% on supported platforms | MVP release |
| Reliable scraping | Share of supported-platform vacancy pages parsed successfully | n/a | ≥ 90% | MVP release |
| Quality of matching | Agreement between match score ranking and manual relevance rating on a test set | n/a | Positive correlation on a hand-labeled sample | MVP release |
| Deduplication | Duplicate vacancies shown to the user | n/a | < 5% of listings | MVP release |
| Mobile usability | Dashboard works on phone/tablet viewports | n/a | All main screens usable at 360 px width | MVP release |
## Success Criteria

### Must Have

- The extension scrapes vacancies from at least two job platforms and sends them to the server.
- The server deduplicates incoming vacancies and serves up-to-date selectors to the extension without a client restart.
- The AI assistant returns a match score for a resume–vacancy pair and generates a cover letter.
- The user can submit an application from the extension and see its status in the PWA.
- Personal data and credentials are stored only on the client device.
- The PWA dashboard is usable on desktop and mobile viewports.
- The backend, data collector and databases start in an isolated container network with a single command.
- The API between the PWA, the extension and the backend is fully documented.

### Nice to Have

- Fully automatic submission mode with user-defined rules.
- Community sharing of successful form-field mappings and selectors, with validation.
- Resume export to both PDF and DOC from multiple templates.
- Captcha relay from the extension to the PWA for resolution by the user.

## Non-Goals

- A cloud service that stores user credentials or applies on the user's behalf from the server.
- Bypassing platform security measures.
- Support for every job platform; only a limited set is supported in the MVP.
- Being an employer-side tool or a job board of its own.
